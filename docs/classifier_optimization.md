# Fermi-Dirac classifier: bottlenecks and optimization history

Consolidated from four June-2026 working documents (`bottleneck_analysis.md`,
`optimization_roadmap.md`, `pennylane_optimization_summary.md`,
`quick_reference_phase1.md`), which this file replaces. Measured
benchmark results live in `scaling_comparison.md` and
`paper_comparison_guide.md`; the code of record is
`figures/quantum_training_impls.py` and `notebooks/pennylane/`.

> **Scope: the SINGLE neuron.** Everything below assumes the loss is applied to
> the Hamiltonian by functional calculus, which is what makes it linear in each
> `ρ_m` and lets `R±` collapse the dataset once, before training. The hybrid
> **network** ([`HYBRID_BACKPROP.md`](HYBRID_BACKPROP.md), [`qnn/`](../qnn/README.md))
> breaks that assumption: its loss is nonlinear in `ρ_m`, so optimization #3 and
> #4 below do not carry over unchanged. What survives is a per-neuron aggregate
> re-formed each epoch, which still makes bottleneck #2 — the eigendecomposition
> — independent of dataset size. See `qnn/README.md`'s cost table.

## Bottleneck analysis (June 2026, still accurate)

Per epoch, for n qubits, p Pauli parameters, and Ns training states:

| # | Operation | Cost | Status |
|---|---|---|---|
| 1 | Dense Hamiltonian build from Kronecker products | O(4^n · p) time+memory | mitigated (sparse Pauli cache) |
| 2 | Eigendecomposition `eigh(H)` | O(8^n), twice per epoch | inherent to the FD-machine formulation; dominates at large n |
| 3 | Manual gradient `dfj` per parameter per state | O(8^n · p · Ns) | **eliminated** (vectorized + label aggregation) |
| 4 | Loss trace per state | O(4^n · Ns) | **eliminated** (aggregated density matrices) |

## What was actually implemented

- **Phase 1 — vectorized gradients** (`compute_loss_and_grads_vectorized`,
  now in `notebooks/pennylane/phase1_optimization.ipynb`): one
  eigendecomposition per parameter vector, all states rotated to the
  eigenbasis in batched einsum. Measured ~1.5x at n=3 over the notebook
  original.
- **Phase 2 — label-aggregated density matrices** (`optimize_phase2` in
  `notebooks/pennylane/logloss_pennylane.ipynb`, reproduced in
  `figures/quantum_training_impls.py::run_pennylane`): the logistic loss and
  its gradient depend on the training set only through
  R± = Σ_{y_i=±1} ρ_i, so per-state work drops out of the epoch loop
  entirely — cost becomes independent of Ns after a one-time aggregation.
  Combined with sparse precomputed Pauli terms, this is the production
  training pass. Measured results: `results/logloss_*qubit_phase2.csv`,
  `results/pennylane_*.csv`, figures in `figures/`.
- **Matrix-free fused Pauli kernels + adaptive Chebyshev loss** (also in
  `logloss_pennylane.ipynb`: `build_fused_pauli_kernel`,
  `compute_loss_and_grads_chebyshev`, `resolve_array_backend`): applies
  H(ω) without materializing 2^n × 2^n matrices and replaces the exact
  spectral loss with a Chebyshev expansion of adaptive degree — the
  "symbolic Hamiltonian" tier from the original roadmap. Benchmarked by
  `benchmarks/benchmark_scaling.py` (CSR vs fused payload sizes) and
  covered by `tests/test_notebook_equivalence.py`. Note: this
  implementation was accidentally dropped from the notebook in the
  2026-06-29 rebase and restored from commit `b373b395` on 2026-07-13.
- The original-vs-optimized equivalence is enforced by
  `tests/test_notebook_equivalence.py`; scaling and paper-style comparisons
  are generated by `benchmarks/benchmark_scaling.py` and
  `benchmarks/benchmark_paper_comparison.py`.

**Gradient correctness note:** the paper-faithful notebook divides the
gradient term `H_j` by T inside `dfj` — an extraneous factor relative to
Theorem 5 / Eq. (63) of the paper. The optimized implementations use the
correct `dH/dw_j = H_j`. See "Important note about gradients" in
`paper_comparison_guide.md`; `run_original` in
`figures/quantum_training_impls.py` also fixes it so comparisons are
apples-to-apples.

## Not implemented (evaluated, deliberately skipped or deferred)

- **QNode/parameter-shift autodiff** (the original Phase-1 proposal): not
  adopted — the loss is a spectral function of H(ω), not a circuit
  expectation, so the label-aggregation route was both simpler and faster.
- **JAX/GPU backends**: `resolve_array_backend` leaves the seam open, but no
  GPU backend has been wired in; hardware-dependent, estimated 5–20x.

Historical planning estimates ("100–500x total") in the superseded docs
were speculative; the numbers above reflect what was measured.
